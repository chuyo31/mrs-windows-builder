PROMPT 09 — AUDITAR Y CORREGIR WORKSPACE/MOUNT DE REMOVALENGINE

Tenemos dos pruebas REAL de MRS Windows Builder sobre Windows 11 26H2 Pro.

Clipchamp.Clipchamp se elimina correctamente y DISM ejecuta:

/Unmount-Wim /MountDir:"...\mount" /Discard

El log real confirma:

Received unmount request.
Unmount complete.
Wimserv stopped.

Sin embargo, después de la operación:

dism /English /Get-MountedWimInfo

sigue mostrando una entrada MRS:

Mount Dir:
...\workspaces\<A>\mount

Image File:
...\workspaces\<B>\source\install.wim

Status:
Invalid

donde <A> y <B> SON WORKSPACES DIFERENTES.

Ejemplo real:

Mount:
63f4dfbb4ea1447194712d5226d3bb9b

WIM:
191d41cd5c3f4f1ea025b897998e4ec4

Ambos directorios existen.

IMPORTANTE:
NO asumir que esto significa automáticamente que /Unmount-Wim haya fallado.
El log demuestra que DISM informa "Unmount complete" y "Wimserv stopped".

OBJETIVO:

Auditar completamente el ciclo de vida:

WorkingImageFactory
→ workspace
→ source/install.wim
→ mount directory
→ Mount-Wim
→ modificaciones
→ Commit
→ Unmount
→ verificación
→ limpieza/finalización.

Queremos determinar exactamente por qué DISM termina registrando una combinación de mount y WIM pertenecientes a workspaces distintos y por qué queda una entrada Status=Invalid.

PRIMER PASO OBLIGATORIO:
Antes de modificar código, inspecciona:

1. WorkingImageFactory.
2. Workspace creation.
3. Workspace paths.
4. RemovalEngine.ExecuteAsync.
5. cualquier método que cree WorkspaceContext/WorkspaceInfo.
6. cualquier código que genere GUID de workspace.
7. MountWimAsync.
8. UnmountWimCommitAsync.
9. UnmountWimDiscardAsync.
10. RemovalVerifier.
11. VerifyExecutionAsync de MainWindow.
12. cualquier segundo ciclo de inventario que vuelva a montar la imagen.

Traza los objetos/path exactos que se pasan entre estas fases.

Busca específicamente:
- creación accidental de dos workspaces para una misma operación;
- reutilización de WorkspaceContext incorrecto;
- creación de workspace en ImageService/InventoryService durante la verificación;
- creación de un nuevo GUID cuando debería reutilizarse el workspace de RemovalEngine;
- mount path de un workspace y WIM path de otro;
- verificación que use un workspace distinto;
- finally que opere con un contexto distinto;
- referencias estáticas/globales;
- carreras async;
- operaciones que monten/desmonten sin que RemovalEngine sea consciente.

NO hagas todavía una refactorización grande.

SEGUNDO:
Añade logging estructurado de una operación completa, incluyendo:

OperationId
WorkspaceId
SourceWimPath
WorkingWimPath
MountDir

y registrar esos cinco valores en:

- creación de workspace;
- Export-Image;
- Mount-Wim;
- cada acción;
- Commit;
- Unmount;
- Verify;
- cleanup/finally.

Los valores deben permitir comprobar que SIEMPRE se usa el mismo contexto de operación.

TERCERO:
Revisa especialmente RemovalVerifier.

El verificador NO debe crear ni utilizar silenciosamente un workspace distinto que pueda confundirse con el workspace principal.

Si necesita crear una imagen temporal para comparar:
- debe tener un workspace explícitamente identificado como VERIFY;
- no debe dejar ningún montaje;
- debe registrarse claramente;
- debe quedar fuera del ciclo principal;
- debe limpiarse de forma segura.

CUARTO:
Añade una prueba automatizada que demuestre:

Una operación RemovalEngine utiliza exactamente un WorkspaceContext principal.

El MountDir y WorkingWimPath pertenecen al mismo WorkspaceId.

Si se detecta una combinación cruzada, el test debe fallar.

Añade también tests para:
- éxito;
- error;
- cancelación;
- commit;
- discard;
- verifier.

QUINTO:
NO ejecutar Cleanup-Mountpoints.
NO borrar manualmente registros DISM.
NO cambiar el comportamiento de DISM para ocultar el problema.

La aplicación debe considerar éxito únicamente cuando:
- la operación terminó;
- commit/discard terminó;
- unmount terminó;
- la verificación terminó;
- y se puede demostrar que el montaje de ESA operación ya no existe.

Pero NO considerar un Get-MountedWimInfo con una entrada Invalid como prueba suficiente de que el Unmount falló si el log de DISM confirma "Unmount complete". Analizar primero el origen de esa entrada.
